# Security policy

## Supported versions

Security fixes are made on the latest maintained version. There is no separate long-term-support branch at this time.

## Reporting a vulnerability

Do not disclose vulnerabilities publicly. Use GitHub's **Report a vulnerability** action in the repository Security tab when private vulnerability reporting is enabled. If it is unavailable, contact the maintainer privately through their GitHub profile and include the affected version, operating system, and a minimal sanitized reproduction.

Do not send recordings, spreadsheets, project files, absolute local paths, or other sensitive study data. The application processes data locally; diagnostic files and export records can contain source paths and column names, so inspect and redact them before sharing.

There is currently no guaranteed response-time commitment. Reports will be acknowledged and assessed as maintainer availability permits.
